# Практический кейс: root на Яндекс Станции Лайт 1 через factory → OTA → ADB

Опыт владельца Lite 1 (**YNDX-00025, `yandexmicro`**), подтверждённый **27 октября 2026 года**; последующая проверка — 4 ноября. Этот материал дополняет [основное руководство по root](root.md) и [настройку постоянного SSH](ssh.md), не заменяет таблицу совместимости.

!!! info "Проверено на одном устройстве"
    Здесь приведён **результат реально выполненной процедуры**. Он не доказывает совместимость всех версий Lite, Mini 1/2, Lite 2 или других колонок. Перед действиями проверяйте свою платформу, свежую wiki и восстановление из backup.

## С чем столкнулись

На штатной версии `0.372.1.8.4790672876.20261019.300` колонка нормально слышала голос и управляла домом, однако ADB `5555` и Glagol `1961` не принимали подключения. Внешний unlock DNS возвращал желаемые настройки `remoteActivation`/`network`, но **это был ответ сервера на диагностический запрос**. Доказательства успешного запроса самой колонкой не было.

Позднее выяснилось, что при синхронизации со стендом прошивка может отвергать сертификат: `TLSV1_ALERT_UNKNOWN_CA`. Поэтому даже успешные DNS и TCP не означают, что root доступен.

## Что подтвердилось при удачном проходе

1. Физический сброс привёл именно к factory-сборке `0.4.1.5.1180614597.20220111.factory-3.factory`.
2. Сначала factory ожидала OTA. Локальный диагностический сервер был настроен так, чтобы **единожды** предложить совместимую подписанную официальную прошивку `0.369.1.46.4778262442.20261013.297` строго для `yandexmicro`.
3. Устройство полностью скачало обновление (66 814 464 байта), установило его, затем **само** сообщило `.46` в `/get_sync_info`. Только после этой стадии стал доступен root ADB.
4. `adb shell id` показал `uid=0(root)`. Не использовали открытый порт или ответ DNS как замену этому тесту.
5. Создали индивидуальный бэкап и SSH root на порту 2222, **только по ключу**, запретили автоматическое OTA штатными механизмами данной платформы.
6. Восстановили обычный DNS, остановили временный HTTP/HTTPS стенд и выполнили **реальную перезагрузку**. Новый `boot_id`, рабочий SSH root, ADB root, системный раздел `ro` и отсутствие `updatesd` подтвердили постоянство изменений.

| Параметр | Значение |
| --- | --- |
| Модель | `yandexmicro` |
| Версия | `0.369.1.46.4778262442.20261013.297` |

!!! warning "Это не обычный ZIP"
    Несмотря на расширение `.zip`, подписанный OTA-файл начинается с `070702` (cpio). Не перепаковывайте его, чтобы «исправить архив». Проверяйте SHA-256 и manifest, а не только расширение.

## Ошибки, которые стоит исключить заранее

- **Не тот образ/путь:** у стенда ожидается модельный путь `firmware/yandexmicro/` и корректный manifest; одна копия в корне `firmware` не равнозначна рабочему серверу.
- **Подмена для всей сети:** безопаснее временно переключать только домены/клиент **одной выбранной колонки**, сохраняя обычные DNS у остальных устройств. Телефон с «Домом с Алисой» не должен попадать в подмену, иначе его HTTPS тоже может сломаться.
- **Сброс без стенда:** сначала проверка HTTP/HTTPS/TLS, полной отдачи файла, Range и отката DNS, только потом физический factory reset.
- **Неправильный критерий готовности:** нужна вся цепь от запроса реальной колонки до root ADB, а затем SSH после reboot и уже при нормальном DNS. Проверка одной только `/get_sync_info` с тестового компьютера не подходит.
- **Надёжность backup:** один из дампов bootloader в этом эксперименте оказался частичным из-за ошибок чтения/ECC. Live-копия UBI — тоже не обязательно согласованный образ восстановления. Эти ограничения надо отмечать в манифесте.

## Для других моделей

Mini 1 (ранняя модель) имеет отдельный описанный [USB/TPL-путь](root-mini1-usb.md), поэтому не следует автоматически повторять Lite-процедуру. Для Mini 2 используется **другая** версия OTA `.46…299`. После возврата штатной облачной синхронизации ADB у Mini 2 может выключаться, а постоянный SSH остаётся. Поэтому проверяйте каждую модель независимо и не переносите её образ, root-маркеры и команды на другие.

## Что сохранять в собственном журнале

Дата и модель; до/после версия прошивки; подтверждение factory; полный SHA-256/размер и происхождение OTA; журналы HTTPS `check_updates` и `get_sync_info` **без account payload**; `adb shell id`; новое `boot_id`; результат SSH с ключом и без него; `rootfs ro`, состояние updater; проверку нормального DNS/голоса; SHA-256/ограничения резервных копий. Сохраняйте реальные ID, ключи и логи **в частном архиве, не в публичном репозитории**.

## После root

Root не означает, что нужно заменять оригинальный `maind`, микрофоны или прошивку целиком. Один из практических сценариев — отдельный [Quasar Bridge](../recipes/llm.md): штатная Алиса обрабатывает активацию и голос, а собственная текстовая LLM получает только выбранные запросы. Потоковый TTS через UniProxy — отдельная задача, не часть получения root.
